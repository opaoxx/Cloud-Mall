# CloudMall 前端体验第二轮改造方案

## 问题范围

本轮基于首页、目录、详情、结算、订单详情和地址管理截图，修复展示层缺陷并补足现有后端秒杀能力的可发现入口。截图仅作为 UI 证据，不改变已冻结的 API、金额、时间和认证契约。

## 交付顺序与 Git 回滚点

1. `diagnose`: 记录截图问题，复现布局与路由问题；确认 StockApplication 启动耗时来自 88,476 条库存逐条写 Redis。
2. `catalog-detail`: 修复搜索按钮换行、商品图文重叠、销量排序、详情规格卡片；提交独立 commit。
3. `checkout-order-account`: 折叠新增地址表单，结构化订单地址快照，统一地址操作按钮样式；提交独立 commit。
4. `activities`: 修正三个活动区入口，接入真实秒杀活动和秒杀下单入口，补充明确标注为演示的领券视觉区；提交独立 commit。
5. `stock-startup`: 以 Redis pipeline 批量重建普通库存缓存，保留数据库校准语义；基于启动日志和测试确认启动更快；提交独立 commit。

每阶段完成后运行适用测试并检查 `git diff --check`。数据库备份、运行日志和浏览器截图留在 `.codex/runtime/`，不提交仓库。

## 各项设计

### 目录与详情

- 搜索按钮设置固定最小宽度、禁止换行，移动端仍保持可点击。
- 商品卡片让图片区和信息区成为明确的垂直布局，图片 `display:block`、容器裁剪溢出，标题最多三行并固定信息区高度。
- 目录新增“销量优先”选项，使用现有 `product_hot_stat.view_count`（ETL 时映射源 `sold`）排序，参数命名为 `sales`，后端白名单映射为 SQL，未知值回退热门排序。
- 商品详情把 `product.parameters` 中的品牌和规格渲染为高对比信息卡；SKU 规格用可选中边框框展示，JSON 对象转为键值文本，不新增后端字段。

### 结算与订单

- 新增地址表单默认收起；地址下拉增加“＋新增收货地址”，只有选择该项时展开表单。保存成功后自动收起并选中新地址，保留现有 `POST /users/me/addresses`。
- 订单详情对 `addressSnapshot` 同时兼容对象和 JSON 字符串，只展示收货人、手机号、详细地址三项，使用标签和值卡片，绝不把原始 JSON 直接输出。
- `/addresses` 页面“设为默认、编辑、删除”统一使用带边框按钮，并提供 hover/focus 状态。

### 活动与秒杀

- “今日上新”跳转真实 `sort=latest`；“数码精选”和“生活补给”跳转对应分类 ID，不再把关键词强行写入搜索框。
- 迁移脚本创建一个当前可用的 CloudMall 秒杀活动，引用已导入的真实 SKU，写入活动时间、限量库存和 Redis 元数据；活动 ID 固定，脚本可重复执行。
- 首页通过现有 `GET /api/seckill/activities/{id}` 和 `GET /api/products/skus/{skuId}` 读取活动状态、剩余库存和商品信息，点击进入既有 `/seckill/{id}` 下单页；不伪造活动列表接口。
- 现有活动契约没有活动价/原价字段，因此 UI 展示真实 SKU 价格并标注“限量秒杀价”；不在前端虚构折扣金额。领券区仅作为“演示活动”静态入口，不声称已实现券领取或抵扣。

### StockApplication 启动

- 保留 `StockCacheReconciler` 的数据库事实源和全量覆盖语义，将逐条 Redis `SET` 改为每批 10,000 条的 `MSET`；启动后仍保证每个 `stock:available:{skuId}` 与数据库可用库存一致。
- 用 `StopWatch`/启动日志记录缓存重建前后耗时；不关闭一致性恢复、不绕过秒杀台账恢复，不改端口或中间件配置。
- 后续定时审计的 `KEYS` 改造不纳入本轮，避免扩大范围。

## 验收标准

- 目录搜索按钮横向显示；商品卡片标题不覆盖图片，详情品牌/规格和边框选项清晰可见。
- 目录选择销量排序后结果按源销量降序；热/最新/价格排序仍可用。
- 结算页首次只显示地址选择；选择新增地址才出现输入表单；订单详情只显示三项收货信息。
- 三个首页活动入口不污染搜索框；秒杀卡片能读取活动状态/库存并进入真实秒杀链路；领券区明确为展示演示。
- 地址管理操作按钮有边框和焦点样式。
- StockApplication 启动日志显示库存缓存重建阶段；批量写入后服务可正常监听 8085，库存/秒杀测试不回归。
- 前端 lint/test/build、后端相关 Maven 测试和真实浏览器回归全部通过。
