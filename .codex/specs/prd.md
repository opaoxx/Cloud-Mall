# CloudMall 云购微商城产品需求规格

## 1. 文档定位

- 项目：CloudMall 云购微商城。
- 依据：`微服务电商实战项目开发计划书.md` 与项目根目录 `AGENTS.md`。
- 范围：用户、商品、购物车、订单、库存、模拟支付、秒杀及必要的运营支撑。
- 当前文档只描述可实现的业务需求与验收口径，不包含业务实现代码、SQL 初始化脚本或具体部署脚本；本地部署编排边界以架构规格中的 Docker Compose 设计为准。
- 项目定位为个人技术实战项目，优先保证业务闭环、技术场景可复盘，不承诺生产级高可用和生产安全。

## 2. 目标与角色

### 2.1 项目目标

用户能够完成“注册/登录 → 浏览/检索商品 → 加入购物车 → 结算下单 → 库存扣减 → 模拟支付 → 订单完成”的闭环；系统同时展示 Redis、RabbitMQ、Seata、Sentinel、Sharding-JDBC、Elasticsearch、链路追踪和监控的真实落地场景。

### 2.2 用户角色

| 角色 | 能力 |
| --- | --- |
| 未登录用户 | 浏览已上架商品、分类和搜索结果；不能提交需要身份的购物车、订单和支付操作 |
| 普通用户 | 注册、登录、维护个人信息、购物车操作、下单、取消未支付订单、模拟支付、查看订单 |
| 管理员/运营人员 | 管理商品、分类、商品参数、上下架和秒杀活动；本地练习环境允许预置 `admin/admin`，普通注册用户默认 `USER`，管理接口要求 `ADMIN` |

## 3. 业务闭环

1. 用户注册并登录，系统返回登录态；登录态写入 Redis，后续请求经网关鉴权。
2. 用户浏览分类或通过商品关键词检索商品；仅展示已上架且可售商品。
3. 用户在商品详情页选择规格和数量加入购物车；购物车数据以 Redis 为核心，支持跨设备同步。
4. 用户在购物车勾选商品进入结算；系统重新读取商品价格和库存，不信任前端提交的价格。
5. 订单服务创建待支付订单，并协调库存服务预扣；跨服务一致性通过 Seata，异步事项通过 RabbitMQ。
6. 用户发起模拟支付；支付成功后通过回调/消息同步订单状态，库存预扣转为已售。
7. 未支付订单达到超时阈值后由 RabbitMQ TTL + DLX 延迟消息处理关单并回滚库存。
8. 秒杀活动走独立高并发路径：Redis 预扣库存、Sentinel 限流/热点参数保护、RabbitMQ 异步削峰，最终由订单和库存完成一致性确认。

## 4. 功能需求

### 4.1 用户服务

- 注册：校验必填身份信息唯一性，密码不得以明文返回；重复账号返回明确错误。
- 登录：校验凭据，生成 Redis 不透明 Token，写入 Redis；成功后返回用户基础信息和 Token。Token 通过 `Authorization: Bearer <token>` 传递，登录态 TTL 为 2 小时。
- 登出：使当前登录态失效。
- 个人信息：查询和修改允许修改的资料；用户 ID 以服务端登录态为准。
- 权限：网关执行基础鉴权，用户服务执行资源权限判断；管理员功能仅对具备管理员权限的账号开放。

### 4.2 商品服务

- 商品：创建、查询详情、分页列表、修改、上下架；商品包含名称、主图、描述、价格、库存展示、分类和可选规格等信息。
- 分类：分类新增、修改、删除/停用、列表查询；分类层级深度待确认。
- 参数：维护商品参数模板或商品参数值；参数具体类型待确认。
- 搜索：Elasticsearch 支持关键词模糊检索、分类筛选和基础排序；MySQL 作为业务事实数据源。
- 热度：记录浏览/检索等热度事件并支持排序；统计口径、衰减周期待确认。
- 一致性：下单时以商品服务/订单快照返回的价格和名称为准，订单保存不可变快照。

### 4.3 购物车服务

- 登录用户按商品/规格新增、修改数量、删除和查询购物车项。
- 支持勾选/取消勾选，支持清理已购买或失效商品。
- Redis 保存购物车核心数据；前端可有本地缓存，但服务端 Redis 是跨设备同步的权威购物车状态。
- 结算前校验商品仍上架、价格是否变化、库存是否满足；校验失败返回逐项结果，不直接创建订单。
- 购物车不负责最终扣库存，防止以加入购物车代替库存锁定。

### 4.4 订单服务

- 从购物车勾选项创建订单，生成订单号、订单明细快照、金额、收货信息和待支付状态。
- 订单状态至少包括：`PENDING_PAYMENT` 待支付、`PAID` 已支付、`CANCELLED` 已取消、`COMPLETED` 已完成；库存状态至少包括预扣、已扣减、已回滚。
- 查询当前用户订单列表、详情和状态。
- 仅允许用户取消待支付订单；已支付订单取消/退款流程不在本期范围。
- 创建订单必须通过 HTTP Header `Idempotency-Key` 具备幂等保护，重复请求不得产生重复有效订单。
- 超时关单由 RabbitMQ 驱动，关单操作必须幂等并触发库存回滚。
- 订单按时间使用 Sharding-JDBC 分表；业务查询必须携带可路由的时间条件或通过订单号定位。

### 4.5 库存服务

- 维护商品/规格可用库存、预扣库存和已售库存。
- 普通下单执行预扣；支付成功确认扣减；取消/超时/支付失败回滚。
- 扣减必须原子校验可用库存，禁止负库存；重复消息和重复请求不得重复扣减。
- 使用 Seata 参与订单创建与库存扣减的一致性协作；RabbitMQ 处理异步回滚/确认场景。
- 秒杀库存优先预热到 Redis，扣减成功后异步进入订单链路；最终库存以持久化业务状态为准。

### 4.6 支付服务

- 提供模拟支付入口，不接入真实第三方支付。
- 支付请求校验订单归属、金额和当前状态，生成支付记录。
- 模拟成功/失败结果；成功通过回调或消息通知订单服务。
- 回调必须验签语义（模拟场景可使用内部校验）、幂等处理，不能重复更新订单或重复确认库存。
- 待支付订单超时由 RabbitMQ TTL + DLX 订单链路关闭；具体超时时长作为实现配置，不改变本契约。

### 4.7 秒杀

- 管理员配置秒杀商品、活动时间、活动库存和限购规则；活动管理归属商品服务，交易执行由订单/库存协作完成。
- 活动开始前将热点商品信息和可售库存预热至 Redis。
- 秒杀入口经 Gateway、Sentinel 做鉴权、接口限流、热点参数限流和基础防刷；不引入复杂风控系统。
- Redis 原子预扣库存，预扣成功后发送 RabbitMQ 消息异步创建订单；失败快速返回库存不足/活动结束。
- 同一用户同一活动的重复请求必须通过 `Idempotency-Key` 幂等并受限购规则约束；消息消费失败按 RabbitMQ 重试/死信机制处理，并保留可观测失败记录。
- 秒杀订单仍遵循普通订单支付、超时关单和库存回滚规则。

## 5. 非功能需求与约束

- 所有服务通过 Nacos 注册发现和配置管理；Gateway 为前端统一入口。
- Redis 用于登录态、购物车、热点商品、秒杀库存和限流计数；RabbitMQ 用于超时关单、支付通知、库存异步处理和浏览统计。
- Sentinel 用于秒杀限流、熔断降级、热点参数限流；Seata 用于订单与库存、支付与订单的跨服务一致性场景。
- Elasticsearch/Kibana 用于商品检索及日志分析；Micrometer Tracing/Zipkin 用于链路追踪；Prometheus/Grafana 用于 JVM、QPS、响应时间和中间件监控。
- Docker Compose 是本地开发部署编排入口，必须编排 Nacos、MySQL、Redis、RabbitMQ、Seata、Elasticsearch、Kibana、Zipkin、Prometheus、Grafana、Sentinel-Dashboard 和 Nginx；业务服务前期由 IDEA 本地调试，后期再打包 Docker 镜像。Nginx 代理前端静态资源和请求分发。
- 认证中间件遵循 `root/root` 约定；无认证组件不得虚构账号密码。该约定仅适用于本地练习。
- API 金额在 JSON 中使用字符串，Java 使用 `BigDecimal`；API 时间使用 ISO-8601 `+08:00`，数据库使用 Asia/Shanghai 语义的 `DATETIME(3)`。
- 服务间使用 Spring Cloud OpenFeign + Nacos；连接超时 3 秒、读取超时 5 秒，仅对幂等 GET 允许有限重试。Seata 使用 file 模式。
- 商品索引通过 RabbitMQ 异步同步；Trace ID 由 Micrometer Tracing 透传；Prometheus 通过 Spring Actuator 指标端点采集。
- 本地 IDEA 调试端口固定为 Gateway 8080、user 8081、product 8082、cart 8083、order 8084、stock 8085、pay 8086，前端 Vite 使用 5173。为保持 IDEA 本地调试约束和最小运行时复杂度，本期不将七个业务服务纳入 Compose 启动集合；现有业务 Dockerfile 依赖已构建的 `target/*.jar`，业务镜像化与 Compose 扩展留待后续评审。Compose 管理的 Nginx 不改变上述端口基线。
- 本期不引入 Zuul、Eureka、Kubernetes、多级缓存和复杂风控。

## 6. 验收场景

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 注册登录 | 注册成功可登录；登录态可跨请求使用，登出后失效 |
| AC-02 | 商品发现 | 可按分类/关键词查询上架商品并查看详情 |
| AC-03 | 购物车 | 增删改查、勾选、跨设备同步有效；失效商品结算被拦截 |
| AC-04 | 普通下单 | 创建订单保存价格快照；库存不足时订单不形成有效待支付单 |
| AC-05 | 支付 | 模拟成功回调后订单变为已支付且库存确认；重复回调无副作用 |
| AC-06 | 关单回滚 | 待支付订单超时关闭，库存回滚；重复关单不产生副作用 |
| AC-07 | 秒杀 | 限流、库存原子预扣、异步下单；库存耗尽后不超卖 |
| AC-08 | 可观测性 | 跨服务请求可关联追踪，服务指标和错误日志可查询 |

## 7. 设计冻结说明

本轮已冻结 Token、金额与时间格式、幂等 Header、管理员权限、RabbitMQ TTL + DLX、服务间 OpenFeign 超时/重试、Seata file 模式、索引异步同步、Trace/Actuator 观测方式及 IDEA 本地端口。收货地址、分类层级、商品规格、分页排序和退款/售后等非本轮基线内容，按本文件已有业务范围实现，不得擅自扩展为新的业务契约。
