# CM21 SINGLE10 复核通知与同源时钟回执离线契约

2026-10-28，PM 审定：`OFFLINE_REVIEW_PROTOCOL_CONTRACT_GO`。目录 `target/cm21-single10-review-protocol-20261028`，本项仅规格、JSON Schema、合成 fixture、纯离线契约校验器与测试。不实现运行态 mailbox/client/runner integration；不启动压测、Java、JMeter、Docker、SQL、MQ、HTTP 或业务子进程。旧 Java/JMX/runner/review/claims/已归档文件不改，旧 `CM21_BATCH1_SINGLE10_REVIEW_TIMEOUT_UNQUALIFIED` 保持。

## 问题、目标及写入分工

上一轮 pending、Root 读取与迟到尝试之间缺少 runner 自己采集的精确回执；原始尝试时间继续 UNKNOWN，不能由本契约回填。旧摘要 array-half 不是实际 JTL 后半段，后续资格仍须按原始 rows 与真实 JTL 窗口派生，不能以本通知协议替代原资格判断。

Root 本项只在新 target 写合成 bundle/schema/validator/tests；PM 只本规格；QA 只读审计，不自行扩展委派。运行态未来另 scope 实现时，runner 是事件、ordinal、monotonic_ns、pending 和正式 review publication 的唯一写入者；Root 只发显式 OPEN/DECIDE 命令。Root 不提供客户端时刻、不直接改事件、不提交历史补签。runner 处理 OPEN 的时刻只证明已处理该命令，不证明人已读完、已理解或已作判断。

`clockDomain` 是每 run 独立的 32 位小写 hex token，与 runIdentity、pending hash 绑定；不是操作系统跨进程同源证明。未来全部 observedNs 只能由持有该 run 时钟职责的同一 runner 调 `time.monotonic_ns()`。离线校验只证明输入符合约定，不能证明真实进程曾执行这些采样。

## 固定预算与编码

- 纳秒均 strict integer（bool 不算），范围 0..9223372036854775807；浮点旧协议字段只允许有限 int/float，不允许 bool/NaN/Infinity。
- workDeadlineNs = parentAnchorNs + 1080×10^9；outerDeadlineNs = parentAnchorNs + 1200×10^9。
- stageStartedNs ≥ parentAnchorNs 且 < workDeadlineNs−90×10^9；finishDeadlineNs = min(stageStartedNs+300×10^9, workDeadlineNs−90×10^9)；reviewDeadlineNs = finishDeadlineNs。
- pending 发布必须在上述 stage 和 review 截止之间。CLOSING 是关闭开始事件，不是关闭完成证明；未来共享 closing deadline 仍为 min(workDeadlineNs, CLOSING.observedNs+90×10^9)，不续窗。
- JSON UTF-8，无重复 object key、无额外字段、无非有限数、无未知 enum；文件最多 64 KiB、嵌套深度最多 16、总节点最多 1024。先读有界字节再解析，不反序列化代码。JSON Schema 与语义校验共同生效，不把 JSON Schema 不能表达的预算/顺序/hash 关系当作已验证。
- 本契约 SHA256 为 canonical JSON 字节：`json.dumps(value,sort_keys=True,separators=(',',':'),ensure_ascii=True,allow_nan=False).encode('utf-8')`。它是协议内容 hash，不冒充历史原文件字节 hash。原九输入 SHA 则保持原文件字节 SHA 含义。

## bundle 与 pending：闭字段

顶层恰 8 个字段：`schemaVersion`（strict int 1）、`scope`（`SYNTHETIC_REVIEW_PROTOCOL`）、`context`、`pending`、`notification`、`commands`、`review`、`events`。合成 owner/runtime/hash 明确标记合成，不用旧实际身份制造新实际回执。

context 恰 8 字段：`clockDomain`、`pendingSha256`、`parentAnchorNs`、`workDeadlineNs`、`outerDeadlineNs`、`stageStartedNs`、`finishDeadlineNs`、`reviewDeadlineNs`。clockDomain 32 小写 hex，pendingSha256 64 小写 hex，后六项为上述 ns。pendingSha256 必须重算完整 pending canonical SHA。

pending 保持旧 exact 9 字段：`schemaVersion`、`owner`、`mode`、`runIdentity`、`runtimeIdentity`、`inputSha256`、`createdMonotonic`、`finishDeadlineMonotonic`、`reviewDeadlineMonotonic`。schemaVersion strict1，owner/runtimeIdentity 各32小写hex，mode 固定 batch1，runIdentity = owner+`-batch1`。createdMonotonic = PENDING_PUBLISHED.observedNs/10^9，两个截止分别等于 context 对应 ns/10^9。

inputSha256 恰以下 9 个键，值均64小写hex：`ready-copy.json`、`10-baseline-done-copy.json`、`10-finish-done-copy.json`、`10-measurement.jtl`、`10-measurement-independent-audit.json`、`read-only-backlog-observations.jsonl`、`offline-backlog-summary.json`、`functional-audit-10.json`、`functional-auditor-invocation.json`。本项只验证 synthetic map/binding，不重新读取实际业务证据或推导样本。

## notification 与 Root commands

notification 恰 4 字段：`status`（EMITTED 或 FAILED）、`delivery`（恒 UNKNOWN）、`pendingSha256`（等 context）、`remainingNs`（reviewDeadlineNs−PENDING_PUBLISHED.observedNs，严格正）。EMITTED 只说明输出动作，不说明 DELIVERED；没有 Root 回执不冒充已通知到人。FAILED 的当前有限合成轨迹只允许没有 commands/review，等原截止 TIMEOUT，不生成自动 Root UNKNOWN。未来真实通知输出失败不得刷新任何预算。

commands 为数组，最多 2 项。每项恰 5 字段：`kind`（OPEN 或 DECIDE）、`reviewer`（ROOT_LOCAL_OPERATOR）、`contextBindingSha256`（完整 context canonical SHA）、`verdict`（null 或 GO/NO_GO/UNKNOWN）、`basisCodes`（数组）。空数组表示无人发命令；一项只能 OPEN；两项必须 OPEN、DECIDE。OPEN verdict=null、basisCodes=[]。DECIDE 为 Root 主动动作，verdict 非 null，basis 非空且不重复、最多8项，每项来自下节冻结词表。禁止客户端 timestamp、自动 DECIDE、自动 UNKNOWN、自动 GO。

commandSha256 均重算对应整条 command canonical SHA。同一 OPEN/DECIDE 只处理一次，不能用重复命令推进事件 ordinal 或延长 deadline；重复、乱序或非法命令在未来入口返回固定拒绝，不覆盖已有状态。当前 validator 输入出现重复/乱序命令直接不合规，无需模拟无限输入或实现实际文件竞争。

## 原 review payload 与资格门不改

review 为 null 或原 exact 10 字段：pending 的六个 common 字段 `schemaVersion/owner/mode/runIdentity/runtimeIdentity/inputSha256`，再加 `reviewer/verdict/basisCodes/reviewedMonotonic`。common 完全等 pending，reviewer=ROOT_LOCAL_OPERATOR，verdict/basis 完全等 DECIDE。reviewedMonotonic = ROOT_DECISION_SUBMITTED.observedNs/10^9，由 runner 采集赋值而非客户端声称。

GO basis 必须恰原三项：`FULL_ORIGINAL_SERIES_REVIEWED`、`SECOND_HALF_NO_SUSTAINED_GROWTH`、`HTTP_AND_FUNCTIONAL_GATES_PASSED`。其余原允许项：`SUSTAINED_GROWTH_UNAPPLIED`、`SUSTAINED_GROWTH_UNPROJECTED`、`HTTP_OR_ACCOUNTING_FAILURE`、`COVERAGE_UNKNOWN`、`CLOCK_OR_SAMPLE_UNKNOWN`。不扩大原集合、不改原非 GO 语义；NO_GO/UNKNOWN 仍须显式 Root 命令，UNKNOWN 不是服务性能 NO_GO。

原浮点门也必须保持：pending.created ≤ reviewed ≤ ACCEPTED 对应 now < pending.reviewDeadline。同时 ns 的提交和最终接受都严格小于 reviewDeadlineNs；浮点换算边界只可保守拒绝，不能用 ns 结果覆盖原 gate 以放宽。旧 runner 先采 validate now、再重读九 input 的源码顺序未在本项改动；未来 ACCEPTED 必须在**全部最终 hash 闭读和 review 校验后**再由 runner 最后采 observedNs，仍小于原截止。不能只凭及时 SUBMITTED 就接受迟到读回。本项合成反例必须覆盖“提交及时、最终读回/ACCEPTED 到截止或之后”。

## 事件闭字段与有限状态机

events 为 4..6 条数组，每项恰 7 字段：`ordinal`、`kind`、`observedNs`、`commandSha256`、`verdict`、`basisCodes`、`reasonCode`。ordinal 是 strict int 且按数组恰1..N；observedNs 非递减，全部属于同一 context clockDomain 的声明域，不用 mtime、wall、客户端时间替换。

顺序固定：STAGE_STARTED → PENDING_PUBLISHED → [ROOT_OPENED] → [ROOT_DECISION_SUBMITTED] → 唯一终态 ACCEPTED/REJECTED/TIMEOUT → CLOSING。方括号可选；SUBMITTED 必须先 OPENED。没有 command 的事件 commandSha=null；OPENED 对应 OPEN hash，SUBMITTED 和与该决定相关终态对应 DECIDE hash。ROOT_OPENED 必须 pending ≤ observed < reviewDeadline；SUBMITTED ≥ OPENED，可在截止后（只能拒绝，不可接受）。

| kind | verdict / basis | reasonCode | 其它条件 |
| --- | --- | --- | --- |
| STAGE_STARTED | null / [] | STAGE_STARTED | observedNs=context.stageStartedNs，commandSha=null |
| PENDING_PUBLISHED | null / [] | PENDING_READY | observedNs 对应 pending.created，commandSha=null |
| ROOT_OPENED | null / [] | OPEN_HANDLED_NOT_HUMAN_READ_PROOF | 对应 OPEN，一次 |
| ROOT_DECISION_SUBMITTED | DECIDE 的值 | ROOT_COMMAND_HANDLED | 对应 DECIDE，一次 |
| ACCEPTED | DECIDE 的值 | ACCEPTED_AFTER_FINAL_READBACK | 提交后全部最终读回后的采样；及时双门通过；review 非null |
| REJECTED | 有 DECIDE 则等其值，否则 null / [] | 下列固定拒绝原因之一 | review 有 DECIDE 则非null；无 DECIDE 则null |
| TIMEOUT | null / [] | REVIEW_WINDOW_EXPIRED | observedNs≥reviewDeadline；无 DECIDE，review=null，commandSha=null |
| CLOSING | null / [] | NORMAL_CLOSE_REQUESTED 或 SAFE_ABORT_REQUESTED | observedNs≥终态且<workDeadline；commandSha=null |

REJECTED reasonCode 仅 `REVIEW_NOT_TIMELY`、`INPUT_HASH_CHANGED`、`REVIEW_VALIDATION_FAILED`、`PROTOCOL_IO_FAILURE`。REVIEW_NOT_TIMELY 必须有 DECIDE 且最终 observedNs≥reviewDeadline，或因原浮点严格门被保守拒绝；INPUT_HASH_CHANGED/REVIEW_VALIDATION_FAILED 必须有 DECIDE；PROTOCOL_IO_FAILURE 可在无 Root 决定时发生，不能据此制造决策。合成 REJECTED 只是固定失败记录的合法形状，不证明实际文件漂移/IO 发生。无法保存最后事件的真实故障是证据缺失，不能补造为完整合规轨迹。

REJECTED 使用 DECIDE hash（如有）；没有 DECIDE 则 commandSha=null。ACCEPTED 是“接受 Root 决定”，不是宣告整个性能/关闭成功。只有 ACCEPTED+verdictGO 后 CLOSING reason=NORMAL_CLOSE_REQUESTED；ACCEPTED+NO_GO/UNKNOWN、REJECTED、TIMEOUT 统一 SAFE_ABORT_REQUESTED。其它事件不得提前签 NORMAL_CLOSE，CLOSING 本身不证明进程已退出或90秒关闭成功。

## 离线校验 API、结果与验证

Root 可实现标准库纯函数 `validate_bundle(bundle)`，不读取时钟/环境/原 runner、不操作 mailbox、不起子进程；读取入口 `validate_file(path)` 仅对一个有界合成文件做 JSON 严格解析，再调用纯函数。默认 CLI 不执行任何运行态操作。校验结果闭字段建议 `schemaVersion=1,scope=SYNTHETIC_REVIEW_PROTOCOL_VALIDATION,compliant(bool),code,eventCount,terminal,acceptedVerdict`；code=OK 或下列固定词，失败结果不泄露任意输入/异常文本。terminal 与 acceptedVerdict 未能验证时为null。compliant 不表示真实压测通过。

固定 validator 拒绝码：INPUT_OVER_CAP、JSON_INVALID、SCHEMA_INVALID、BOUND_INVALID、BINDING_MISMATCH、BUDGET_INVALID、COMMAND_ORDER_INVALID、EVENT_ORDER_INVALID、CLOCK_INVALID、REVIEW_INVALID、ACCEPTANCE_NOT_TIMELY、TERMINAL_INVALID。校验顺序为有界JSON→结构/类型→绑定/预算→命令顺序→事件顺序/时钟→review与终态。合法的“运行态 REJECTED”轨迹不等同于 validator 不合规，须分别报告。

必要合成正例：Root 及时 GO、及时 UNKNOWN、及时 NO_GO；无人读/通知失败的 TIMEOUT；及时提交但最后采样迟到的合法 REJECTED。必要负例：额外字段/bool冒整数/非有限数/重复JSON键/超大小深度节点；错 clockDomain/context/pending/input/hash；少一个GO依据；无OPEN直接DECIDE；重复命令/ordinal/错时序；客户端时间；通知DELIVERED伪报；无Root自动UNKNOWN；提交及时但ACCEPTED恰截止或之后；TIMEOUT前截止；NORMAL_CLOSE误用于UNKNOWN；改预算/续窗。不得新增实际进程来测试协议；用合成 ns 与哈希固定输入完成。

本轮完成条件是 JSON Schema 与 validator 语义一致、合成正反例通过、原冻结输入保全、PM/QA 独立复核与 diff-check；结论最多 `OFFLINE_REVIEW_PROTOCOL_CONTRACT_VERIFIED`。真实 mailbox 原子性/路径归属/写入竞争、通知交互、真实 monotic_ns 单写者以及最终九输入读回后接受顺序，均留后续单独精确实施规格，不以本轮 pure 测试代替。未另行准入，不开展任何实际重跑。
